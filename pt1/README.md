# Эмулятор UNIX-оболочки — вариант 7

Этапы 1 и 2: консольный прототип, настройки из XML и стартовый скрипт.
Написан на Python, используются только встроенные библиотеки.

## Запуск

Нужен Python 3.9 или новее. Установка пакетов и сборка не требуются.
Команды выполняются из папки `pt1`:

```bash
python3 src/main.py
```

Или через скрипт запуска:

```bash
bash run.sh
```

## Структура

- `src/main.py` — код эмулятора.
- `src/config.py` — чтение и вывод настроек.
- `tests/` — тесты команд, настроек и стартового скрипта.
- `config.xml` — пример конфигурации.
- `examples/` — стартовые скрипты и пример ошибочного XML.
- `scripts/` — скрипты запуска для проверки параметров и ошибок.
- `run.sh` — скрипт запуска.
- `.gitignore` — исключения для служебных файлов.

## Функции и настройки

`main()` читает настройки, выводит их и запускает стартовый скрипт.
Если в скрипте нет `exit`, после него начинается интерактивный ввод.
Для ввода с клавиатуры используется функция `run_repl(vfs_name)`.

`execute_command(line, source="")` разбирает строку через `shlex.split()`.
Первый элемент списка — команда, остальные — её аргументы.
Текст в одинарных или двойных кавычках считается одним аргументом.
Пустая строка пропускается. Функция возвращает `True` при корректной
команде `exit` и `False` во всех остальных случаях. Параметр `source`
добавляет номер строки к сообщениям об ошибках стартового скрипта.

`run_script(path, vfs_name)` читает текстовый файл в кодировке UTF-8,
проходит по строкам и передаёт их в `execute_command()`. Каждая строка
отображается вместе с приглашением, а затем выводится результат команды.
После ошибочной строки выполняется следующая. При `exit` обработка
заканчивается. Если файл нельзя прочитать, программа сообщает об ошибке.

В `src/config.py` находятся три функции:

- `read_args()` читает параметры командной строки через `argparse`.
- `load_config(args)` дополняет незаданные параметры значениями из XML.
- `show_config(args)` выводит итоговые значения для проверки.

## Настройки

| Параметр | Назначение |
| --- | --- |
| `--vfs` | Путь к VFS. На втором этапе файл ещё не загружается. |
| `--script` | Путь к стартовому скрипту. |
| `--config` | Путь к XML-конфигурации. |
| `--help` | Справка по параметрам запуска. |

Все параметры необязательны. Без них запускается обычный ввод команд.
При старте выводятся все три настройки; `None` означает «не задано».

Конфигурация имеет такой вид:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<config>
    <vfs>demo.json</vfs>
    <script>examples/start.txt</script>
</config>
```

Параметры командной строки имеют приоритет над XML. Например, если
передать `--vfs other.json`, вместо `demo.json` будет использован этот путь.
Сам XML всё равно читается: отсутствующий или ошибочный файл вызывает
сообщение об ошибке и завершение программы.

Для простоты все относительные пути считаются от текущей папки терминала.
Поэтому примеры запускаются из `pt1`. Скрипт `run.sh` сам переходит в эту
папку перед запуском Python.

Приглашение содержит имя файла VFS без расширения: для `demo.json`
это `demo> `. Если путь не задан, используется имя `my-vfs`.

## Команды

- `ls [аргументы]` — заглушка, выводит имя команды и список аргументов.
- `cd [аргументы]` — такая же заглушка.
- `exit` — завершает программу. Аргументы не допускаются.

У `ls` и `cd` пока нет ограничений на аргументы: они только выводятся.
Работа с файлами и переход между папками относятся к последующим этапам.

Неизвестная команда, незакрытые кавычки и аргументы у `exit` вызывают
сообщение об ошибке. После ошибки программа продолжает принимать команды.
Ctrl+C и окончание ввода (Ctrl+D в macOS/Linux) завершают эмулятор.

## Пример интерактивной работы

```text
VFS: None
Стартовый скрипт: None
Конфигурация: None
my-vfs> ls
Команда: ls; аргументы: []
my-vfs> cd
Команда: cd; аргументы: []
my-vfs> cd "my documents"
Команда: cd; аргументы: ['my documents']
my-vfs> ls "file one.txt" 'file two.txt'
Команда: ls; аргументы: ['file one.txt', 'file two.txt']
my-vfs>
my-vfs> hello
Неизвестная команда: hello
my-vfs> cd "broken
Ошибка ввода: No closing quotation
my-vfs> exit extra
Ошибка: exit не принимает аргументы.
my-vfs> ls after-error
Команда: ls; аргументы: ['after-error']
my-vfs> exit
Эмулятор завершён.
```

## Примеры запуска с настройками

Параметры из командной строки:

```bash
bash run.sh --vfs demo.json --script examples/start.txt
```

Параметры из XML:

```bash
bash run.sh --config config.xml
```

Замена настроек из XML значениями командной строки:

```bash
bash run.sh --config config.xml --vfs other.json \
    --script examples/interactive.txt
```

В `examples/start.txt` есть кавычки, пустая строка, неизвестная команда,
незакрытые кавычки, ошибочный `exit extra` и команда после ошибки.
Правильный `exit` завершает программу; строка после него не выполняется.

В `examples/interactive.txt` нет `exit`: после его выполнения можно
вводить команды с клавиатуры.

Для демонстрации ошибок чтения:

```bash
bash run.sh --config examples/broken.xml
bash run.sh --script examples/missing.txt
```

Код завершения: `0` при обычном выходе, `1` при ошибке чтения скрипта,
`2` при ошибке параметров или XML. Ошибочные команды внутри скрипта
пропускаются и сами по себе не меняют код завершения.

## Тестирование

```bash
python3 -m unittest discover -s tests -v
```

14 тестов проверяют команды и кавычки, ошибки, выход, настройки XML,
приоритет каждого параметра CLI и работу стартового скрипта.

Два скрипта ОС показывают запуски со всеми поддерживаемыми параметрами:

```bash
bash scripts/check_config.sh
bash scripts/check_errors.sh
```

Во втором скрипте намеренно вызываются ошибки чтения XML и стартового
скрипта, а затем выполняется обычный запуск с ошибочными командами.
