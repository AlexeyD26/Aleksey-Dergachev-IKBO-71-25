# Граф зависимостей Cargo. Вариант 7

Практическая работа № 2 по конфигурационному управлению.
Программа на JavaScript запускается через Node.js и анализирует пакеты Rust.

Реализованы два этапа:

1. Чтение и проверка шести настроек из YAML.
2. Получение прямых зависимостей указанной версии пакета и их вывод.

## Установка и запуск

Нужен Node.js версии 22 или новее с npm. Отдельной сборки нет.
Команды выполняются в папке проекта:

```sh
npm ci
npm start
```

По умолчанию читается `config.yaml` из текущей папки.
Другой файл можно передать единственным аргументом:

```sh
npm start -- examples/test-config.yaml
```

Другие способы запуска и справка:

```sh
node src/index.js config.yaml
node src/index.js --help
./run.sh examples/test-config.yaml
```

`run.sh` сначала переходит в папку проекта.
Все настройки берутся из YAML; аргумент команды задаёт только путь к нему.

## Настройки

```yaml
package: serde
repository: https://index.crates.io
test_mode: false
version: "1.0.228"
output: graph.png
filter: ""
```

| Параметр | Назначение и проверка |
| --- | --- |
| `package` | Имя пакета: латинские буквы, цифры, `_`, `-`. Первый символ — буква или цифра. В тестовом режиме — одна буква `A`–`Z`. |
| `repository` | Корневой HTTP(S) URL индекса Cargo. В тестовом режиме — путь к JSON-файлу. |
| `test_mode` | Логическое значение `true` или `false`, без кавычек. |
| `version` | Конкретная версия строкой: `1.0.0`. Допустимы суффиксы, например `1.0.0-beta.1+build.2`. |
| `output` | Путь к будущему PNG-файлу. Проверяются расширение и возможность записи. |
| `filter` | Подстрока для исключения пакетов. Будет применяться при построении графа на этапе 3. |

Все шесть параметров обязательны, лишние ключи считаются ошибкой.
Строки, кроме `filter`, не могут быть пустыми.
Пути в `repository` и `output` считаются относительно папки YAML-файла.
Папка для изображения должна существовать.
На этапе 2 изображение ещё не создаётся.

## Как получаются зависимости

Используется HTTP-индекс Cargo: `https://index.crates.io`.
Адрес сайта `https://crates.io` вместо адреса индекса не подходит.

Программа сама составляет путь к файлу пакета по правилам Cargo:

| Длина имени | Пример пути |
| --- | --- |
| 1 символ | `1/a` |
| 2 символа | `2/ab` |
| 3 символа | `3/a/abc` |
| От 4 символов | `se/rd/serde` |

Имя в пути приводится к нижнему регистру.
Файл скачивается встроенной функцией `fetch`.
Каждая строка файла — JSON с данными одной версии пакета.
Программа находит указанную `version` в поле `vers` и читает массив `deps`.

Cargo и библиотеки для получения зависимостей не используются.
Формат описан в [официальной документации Cargo](https://doc.rust-lang.org/cargo/reference/registry-index.html).

## Пример с реальным пакетом

С настройками из `config.yaml` команда `npm start` выводит:

```text
Прямые зависимости serde@1.0.228:
- serde_core =1.0.228 [normal]
- serde_derive ^1 [normal, optional]
```

Для проверки другой версии замените `version` в YAML и запустите снова.

Выводятся все объявленные прямые зависимости:
`normal` — обычные, `dev` — для тестов, `build` — для сборки.
Также показываются признак `optional`, ограничение платформы и имя,
под которым переименованная зависимость используется внутри пакета.

`^1`, `~2.0` и подобные значения — ограничения версий из индекса.
Программа пока не выбирает конкретные версии зависимостей и не обходит их.
Необязательные зависимости и зависимости других платформ не исключаются.

## Тестовый режим без интернета

В `examples/repository.json` задан небольшой репозиторий:

```json
{
  "A": ["B", "C"],
  "B": ["C"],
  "C": []
}
```

Команда `./run.sh examples/test-config.yaml` выводит:

```text
Прямые зависимости A:
- B [normal]
- C [normal]
```

Читается только список выбранного пакета. Сеть не используется.
В тестовом файле версии отсутствуют, поэтому настройка `version`
в этом режиме не участвует в выборе данных.
Фильтрация и полный обход графа будут реализованы на этапе 3.

## Тесты и ошибки

```sh
npm test
```

Тесты проверяют настройки, пути в индексе, выбор версии, все виды
зависимостей, тестовый режим, HTTP-ошибки, сетевой сбой и тайм-аут.
CLI проверяется через локальный HTTP-сервер на `127.0.0.1`.
Для запуска тестов интернет не нужен. Временные файлы удаляются после тестов.

Сообщения об ошибках выводятся в stderr с префиксом `Ошибка:`.
Код завершения при ошибке — 1, при успехе — 0.
Пакет, который не существует, даёт ошибку HTTP 404.
Если пакет есть, но указанной версии нет, выводится отдельное сообщение.
Время ожидания сетевого запроса ограничено 10 секундами.

Для проверки ошибок настроек изменяйте по одной строке в копии YAML:

| Значение | Причина ошибки |
| --- | --- |
| `package: "bad name"` | Пробел в имени пакета. |
| `repository: "not-a-url"` | Некорректный URL. |
| `test_mode: "false"` | Строка вместо логического значения. |
| `version: "latest"` | Отсутствует конкретный номер версии. |
| `output: "graph.jpg"` | Нужно расширение PNG. |
| `filter: 123` | Число вместо строки. |

## Как устроен код

`src/index.js` — запуск программы.
Функция `main` читает настройки и вызывает получение зависимостей.
Функция `printDependencies` выводит результат.
Внешний `try/catch` перехватывает ошибки.

`src/config.js` — проверки настроек первого этапа:
`loadConfig` читает YAML; `validateFields` проверяет ключи;
`validateValues` — типы и значения; `isVersion` — номер версии;
`validateRepository` — URL или тестовый файл;
`validateOutput` — путь к изображению.

`src/dependencies.js` — получение данных второго этапа:

| Функция | Назначение |
| --- | --- |
| `getDependencies` | Выбирает чтение индекса или тестового файла. |
| `getIndexPath` | Строит путь к пакету в индексе. |
| `downloadIndex` | Выполняет HTTP-запрос и обрабатывает сетевые ошибки. |
| `parseDependencies` | Разбирает строки JSON и находит нужную версию. |
| `isDependency` | Проверяет наличие имени и ограничения версии. |
| `readTestDependencies` | Читает прямые зависимости из локального JSON. |

Единственная сторонняя библиотека — [yaml](https://eemeli.org/yaml/).
Она только разбирает файл настроек.
Для HTTP, файлов и тестов используются встроенные средства Node.js.

## Git

Каждый этап сохраняется отдельным коммитом.
Первый этап доступен в истории: в нём выводились шесть настроек.
На втором этапе вывод заменён списком прямых зависимостей.

В Git сохраняются исходники, тесты, настройки и `package-lock.json`.
Установленные зависимости и PNG исключены через `.gitignore`.
