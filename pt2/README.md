# Граф зависимостей Cargo. Вариант 7

Практическая работа № 2 по конфигурационному управлению.
JavaScript, Node.js. Реализованы этапы 1–3:

1. Чтение и проверка настроек YAML.
2. Получение прямых зависимостей указанной версии пакета Rust.
3. Построение графа алгоритмом DFS без рекурсии, фильтрация и обработка циклов.

## Установка и запуск

Нужен Node.js версии 22 или новее с npm. Сборка не требуется.
В папке проекта выполните:

```sh
npm ci
npm start
```

По умолчанию читается `config.yaml` из текущей папки.
Чтобы указать другой файл, передайте его путь:

```sh
npm start -- examples/test-config.yaml
node src/index.js examples/test-config.yaml
./run.sh examples/test-config.yaml
```

`run.sh` сначала переходит в папку проекта.
Справка: `node src/index.js --help`.
Все параметры берутся из YAML, аргумент команды задаёт только путь к нему.

## Настройки

```yaml
package: serde
repository: https://index.crates.io
test_mode: false
version: "1.0.228"
output: graph.png
filter: ""
```

| Параметр | Назначение |
| --- | --- |
| `package` | Имя начального пакета. В тестовом режиме — одна буква `A`–`Z`. |
| `repository` | HTTP(S) URL индекса Cargo или путь к тестовому JSON-файлу. |
| `test_mode` | `true` для локального файла, `false` для HTTP-индекса. |
| `version` | Точная версия начального пакета, например `1.0.228`. |
| `output` | Путь к будущему PNG-файлу. На этапе 3 изображение ещё не создаётся. |
| `filter` | Подстрока имени, по которой пакеты исключаются из анализа. |

Все шесть полей обязательны, лишние ключи считаются ошибкой.
`test_mode` должен быть логическим значением, остальные поля — строками.
Пустая строка разрешена только для `filter`.
В обычном режиме имя пакета содержит латинские буквы, цифры, `_` и `-`;
первый символ — буква или цифра. Версия проверяется на формат SemVer.
Пути в YAML считаются относительно папки самого YAML-файла.
Для `output` проверяются расширение PNG, наличие папки и возможность записи.

## Как работает третий этап

Граф хранится в `Map`: ключ — пакет, значение — массив его зависимостей.
Для настоящего пакета ключ включает версию: `serde@1.0.228`.
В тестовом режиме ключ — буква, например `A`.

Обход выполняется через обычный массив `stack`:

1. Положить начальный пакет в стек.
2. Пока стек не пуст, снять последний элемент через `pop()`.
3. Пропустить пакет, если его имя содержит `filter`.
4. Получить пакет и добавить ребро от его родителя.
5. Если пакет уже есть в графе, повторно его не обходить.
6. Иначе добавить вершину и положить её зависимости в стек.

Зависимости добавляются в обратном порядке, чтобы обход шёл в порядке,
в котором они перечислены в исходных данных. Рекурсивных вызовов нет.
Вершины выводятся в порядке DFS.

Повторно встреченная вершина не обрабатывается второй раз.
При этом ребро к ней сохраняется. Поэтому циклы не зацикливают программу,
а общая зависимость остаётся связана с каждым своим родителем.

Фильтр проверяет настоящее имя пакета, а не его локальный псевдоним.
Сравнение учитывает регистр. Пустая строка отключает фильтрацию.
Исключённый пакет не загружается, его зависимости через эту ветвь не обходятся.
Если исключён корень, выводится сообщение об этом.

## Получение данных и выбор версий

Используется индекс `https://index.crates.io`, а не сайт `https://crates.io`.
Путь к файлу пакета составляется по правилам Cargo:
`1/a`, `2/ab`, `3/a/abc`, `se/rd/serde`.
Файл скачивается через встроенную функцию `fetch`.
Каждая строка файла — JSON с информацией об одной версии пакета.

Начальная версия берётся точно из YAML.
Для каждой зависимости выбирается максимальная версия, подходящая
под её ограничение: `^1`, `~1.2`, `=1.0.0`, `1.*`, `>=1, <2`.
Запись Cargo `1.2.3` понимается как `^1.2.3`.
В первую очередь выбираются версии, которые не отозваны (`yanked`).
Если подходящих обычных версий нет, выбирается отозванная версия
и её вершина явно помечается `[yanked]`. Это позволяет показать старые
объявленные связи; такой граф не означает, что Cargo сможет их установить.
Предварительные версии выбираются только при подходящем явном ограничении.
Разные версии одного пакета представлены отдельными вершинами.
Индекс каждого имени пакета скачивается один раз за запуск.

Анализируются все объявленные связи, включая `dev`, `build`,
`optional` и зависимости других платформ.
Программа строит граф метаданных; согласование версий между ветвями,
вычисление features и обработка Cargo.lock не выполняются.
Для каждой связи версия выбирается независимо.
Зависимость с явно указанным другим реестром вызывает понятную ошибку.

Cargo и библиотеки для получения зависимостей не используются.
Сторонних библиотек две:

- [yaml](https://eemeli.org/yaml/) читает настройки.
- [semver](https://github.com/npm/node-semver) только сравнивает версии.

Правила индекса и диапазонов:
[формат индекса Cargo](https://doc.rust-lang.org/cargo/reference/registry-index.html),
[ограничения версий Cargo](https://doc.rust-lang.org/cargo/reference/specifying-dependencies.html).
Загрузка данных, извлечение зависимостей и DFS написаны в проекте.

## Примеры без интернета

Тестовый JSON задаёт связи буквами:

```json
{
  "A": ["B", "C"],
  "B": ["D"],
  "C": ["D"],
  "D": []
}
```

У каждой вершины должен быть собственный ключ, даже если зависимостей нет.
Некорректные имена и списки вызывают ошибку.
Недостижимые из начального пакета вершины не входят в результат.
Версии в тестовом файле отсутствуют: поле `version` остаётся в настройках,
но при чтении тестовых связей не применяется.

### Общая зависимость

```sh
./run.sh examples/test-config.yaml
```

```text
Граф зависимостей A:
A -> B, C
B -> D
D -> (нет зависимостей)
C -> D
```

### Цикл

```sh
./run.sh examples/cycle-config.yaml
```

```text
Граф зависимостей A:
A -> B
B -> C
C -> A
```

### Фильтр

```sh
./run.sh examples/filter-config.yaml
```

Пакет `B` исключается. Пакет `D` остаётся достижимым через `C`:

```text
Граф зависимостей A:
A -> C
C -> D
D -> (нет зависимостей)
```

### Нет зависимостей

```sh
./run.sh examples/leaf-config.yaml
```

Выводится единственная вершина `D -> (нет зависимостей)`.

## Тесты и ошибки

```sh
npm test
```

Тесты не требуют интернета.
HTTP проверяется на локальном сервере `127.0.0.1`.
Проверяются настройки, точная версия корня, диапазоны Cargo, порядок DFS,
общие зависимости, разные версии, фильтрация, циклы, петли, повторные рёбра,
неизвестные пакеты и повреждённые данные. Временные файлы удаляются.

Ошибки выводятся в stderr с префиксом `Ошибка:`, код завершения — 1.
При успехе код завершения — 0.
Сетевой запрос ограничен 10 секундами.
Есть сообщения для HTTP-ошибок, отсутствующего пакета или версии,
недоступного тестового файла и неподходящих диапазонов.
Результат печатается после завершения обхода, чтобы ошибка не оставляла
на экране неполный граф.

## Файлы и функции

| Файл | Что делает |
| --- | --- |
| `src/index.js` | `main` запускает программу; `printGraph` выводит граф. |
| `src/config.js` | `loadConfig` читает YAML; остальные функции проверяют настройки. |
| `src/dependencies.js` | Читает HTTP-индекс и тестовый JSON, проверяет список зависимостей. Сохраняет функцию `getDependencies` второго этапа. |
| `src/versions.js` | `cargoRange` переводит диапазон Cargo; `selectVersion` выбирает версию. |
| `src/repository.js` | `createRepository` создаёт функцию загрузки пакетов с кешем индексов. |
| `src/graph.js` | `buildGraph` обходит граф через стек; `isExcluded` проверяет фильтр; `addEdge` добавляет ребро без дубликатов. |

Проверки `config.js`: `validateFields` проверяет ключи,
`validateValues` — значения, `isVersion` — формат версии,
`validateRepository` — URL или доступность файла,
`validateOutput` — путь к изображению.

В `dependencies.js` функция `getIndexPath` строит путь к пакету,
`downloadIndex` скачивает файл, `parseIndex` разбирает строки JSON,
`readIndex` объединяет загрузку и разбор.
`parseDependencies` и `findDependencies` находят точную версию.
`getPackageDependencies` и `isDependency` проверяют список зависимостей.
`readTestRepository` читает и проверяет тестовый файл,
`getTestDependencies` возвращает связи выбранной буквы.

Каждый этап сохранён отдельным коммитом.
На этапе 1 выводились настройки, на этапе 2 — прямые зависимости,
на этапе 3 выводится весь построенный граф.
Обратные зависимости и Mermaid/PNG относятся к этапам 4 и 5.
`node_modules` и PNG исключены из Git через `.gitignore`.
