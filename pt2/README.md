# Граф зависимостей Cargo. Вариант 7

Практическая работа № 2 по конфигурационному управлению.
Реализован этап 1: консольная программа читает YAML-файл,
проверяет настройки и выводит их в формате `ключ: значение`.

Язык программы — JavaScript, среда запуска — Node.js.
Анализируемые пакеты относятся к Rust (Cargo).
Получение зависимостей и построение графа относятся к следующим этапам.
На этапе 1 программа не обращается к сети и не создаёт изображение.

## Установка и запуск

Нужен Node.js версии 22 или новее с npm. Отдельной сборки нет.
Команды выполняются в папке проекта:

```sh
npm ci
npm start
```

По умолчанию читается `config.yaml` из текущей папки.
Другой файл можно передать единственным аргументом:

```sh
npm start -- examples/test-config.yaml
```

Прямой запуск, справка и скрипт запуска:

```sh
node src/index.js config.yaml
node src/index.js --help
./run.sh examples/test-config.yaml
```

`run.sh` сначала переходит в папку проекта.
Все настройки берутся из YAML; аргумент команды задаёт только путь к нему.

## Настройки

```yaml
package: serde
repository: https://crates.io
test_mode: false
version: "1.0.228"
output: graph.png
filter: ""
```

| Параметр | Значение и проверка |
| --- | --- |
| `package` | Имя пакета: латинские буквы, цифры, `_`, `-`. Первый символ — буква или цифра. В тестовом режиме — одна буква `A`–`Z`. |
| `repository` | URL с `http://` или `https://`. В тестовом режиме — путь к доступному для чтения файлу. |
| `test_mode` | Логическое значение `true` или `false`, без кавычек. |
| `version` | Строка с конкретной версией: `1.0.0`. Допустимы суффиксы, например `1.0.0-beta.1+build.2`. |
| `output` | Путь к будущему PNG-файлу. Папка должна существовать и быть доступна для записи. Если файл уже есть, проверяется возможность записи в него. |
| `filter` | Подстрока для исключения пакетов на следующих этапах. Пустая строка означает отсутствие фильтра. |

Все шесть параметров обязательны, лишние ключи считаются ошибкой.
Строки, кроме `filter`, не могут быть пустыми.
Пути в `repository` и `output` считаются относительно папки YAML-файла.
На этом этапе проверяется доступность тестового файла, но не его содержимое.

Пример вывода:

```text
package: "serde"
repository: "https://crates.io"
test_mode: false
version: "1.0.228"
output: "graph.png"
filter: ""
```

Кавычки в выводе позволяют отличать строки от логических значений.
В `examples` есть настройки тестового режима и небольшой репозиторий.

## Проверка ошибок

```sh
npm test
```

Тесты запускают в том числе саму консольную программу и проверяют ошибки
каждого параметра, пропущенные и лишние поля, неверный YAML, пути и вывод.
Временные файлы тестов создаются отдельно и затем удаляются.

Чтобы показать ошибки вручную, по очереди измените одну строку в копии
`config.yaml` и запустите программу с этой копией:

| Что изменить | Ожидаемая ошибка |
| --- | --- |
| `package: "bad name"` | Некорректное имя пакета. |
| `repository: "not-a-url"` | Нужен HTTP или HTTPS URL. |
| `test_mode: "false"` | Нужно логическое значение, а не строка. |
| `version: "latest"` | Нужна конкретная версия. |
| `output: "graph.jpg"` | Нужно расширение `.png`. |
| `filter: 123` | Нужна строка. |

Сообщение выводится в stderr с префиксом `Ошибка:`, код завершения — 1.
При успешном запуске код завершения — 0.

## Как устроен код

В `src/index.js` функция `main` получает путь к YAML, вызывает `loadConfig`
и печатает значения циклом. Внешний `try/catch` выводит сообщение об ошибке.

В `src/config.js` находятся функции:

| Функция | Назначение |
| --- | --- |
| `loadConfig` | Читает файл, разбирает YAML, вызывает проверки, возвращает настройки. |
| `validateFields` | Проверяет обязательные и неизвестные ключи. |
| `validateValues` | Проверяет типы, пустые значения, имя пакета и версию. |
| `isVersion` | Проверяет формат версии и её суффиксы. |
| `validateRepository` | Проверяет URL либо доступность тестового файла. |
| `validateOutput` | Проверяет расширение и возможность записи по указанному пути. |

Единственная сторонняя библиотека — `yaml`, она только разбирает YAML.
Документация: https://eemeli.org/yaml/
Для тестов используются встроенные модули Node.js.

## Git

Этап 1 сохраняется отдельным коммитом в формате Conventional Commits:
`feat(config): implement stage 1 YAML configuration`.

В Git сохраняются исходники, тесты, настройки и `package-lock.json`.
Установленные зависимости и PNG исключены через `.gitignore`.
